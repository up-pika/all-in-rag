## 索引的本质

### 问题：为什么需要索引？

```
假设有100万个文档，每次查询都需要：

❌ 没有索引（暴力搜索）：
查询向量 → [计算] 文档1 相似度 
         → [计算] 文档2 相似度
         → [计算] 文档3 相似度
         → ...
         → [计算] 文档1,000,000 相似度
         
时间：100万次计算 = 几秒到几分钟

✅ 有索引（智能搜索）：
查询向量 → [查询索引] → 快速定位相关区域
         → 只计算1000个候选文档
         → 返回Top-10结果
         
时间：1000次计算 = 几毫秒
```

**速度提升：1000倍！**

## 稀疏向量索引

### 1. 稀疏向量的特点

```python
# 示例：词汇表10000维的稀疏向量
文档1: {88: 0.5, 666: 0.8, 999: 1.2}      # 只有3个非零值
文档2: {88: 0.3, 123: 0.9}                # 只有2个非零值
文档3: {666: 0.7, 999: 0.5, 5000: 0.4}    # 只有3个非零值

特点：
- 维度：10,000维
- 非零率：< 0.1% (只有2-3个非零值)
- 9997个维度都是0，非常稀疏！
```

### 2. 倒排索引（SPARSE_INVERTED_INDEX）

**构建过程：**

```
原始数据：
文档1: {88: 0.5, 666: 0.8, 999: 1.2}
文档2: {88: 0.3, 123: 0.9}
文档3: {666: 0.7, 999: 0.5, 5000: 0.4}

↓ 构建倒排索引

倒排索引结构：
维度 → 包含该维度的文档列表
-----------------------------------------
88    → [文档1(权重0.5), 文档2(权重0.3)]
123   → [文档2(权重0.9)]
666   → [文档1(权重0.8), 文档3(权重0.7)]
999   → [文档1(权重1.2), 文档3(权重0.5)]
5000  → [文档3(权重0.4)]
```

**查询过程：**

```
查询向量: {88: 0.6, 999: 1.0}

步骤1：查找维度88
    → 倒排表: [文档1(0.5), 文档2(0.3)]
    → 贡献得分: 
        文档1: 0.6 × 0.5 = 0.30
        文档2: 0.6 × 0.3 = 0.18

步骤2：查找维度999
    → 倒排表: [文档1(1.2), 文档3(0.5)]
    → 贡献得分:
        文档1: 1.0 × 1.2 = 1.20
        文档3: 1.0 × 0.5 = 0.50

步骤3：合并得分
    文档1: 0.30 + 1.20 = 1.50 ★ 最高分
    文档2: 0.18
    文档3: 0.50

结果：[文档1, 文档3, 文档2]
```

**关键优势：**
- ⚡ 只查询非零维度（从10000维降到2维）
- ✅ 100%精确，无精度损失
- 💾 只存储非零值，节省空间

## 密集向量索引

### 1. 密集向量的特点

```python
# 示例：768维密集向量（BGE模型输出）
文档1: [0.23, -0.45, 0.67, 0.12, ..., -0.34]  # 768个浮点数
文档2: [0.56, -0.23, 0.89, -0.11, ..., 0.45]
文档3: [-0.12, 0.78, -0.34, 0.55, ..., 0.23]

特点：
- 维度：768维
- 非零率：≈ 100% (所有维度都有值)
- 每个维度都很重要，无法跳过
```

### 2. AUTOINDEX（自动索引）

Milvus会根据数据量自动选择：

#### 方案A：FLAT（暴力搜索）
**适用：< 8,192条数据**

```
查询向量: [0.1, 0.2, ...]

直接计算：
  → 文档1: cosine(query, doc1) = 0.85
  → 文档2: cosine(query, doc2) = 0.72
  → 文档3: cosine(query, doc3) = 0.91
  → ...
  → 文档N: cosine(query, docN) = 0.68

优势：100%精确
劣势：数据量大时很慢
```

#### 方案B：IVF_FLAT（聚类索引）
**适用：8K - 1M条数据**

**构建过程：**

```
步骤1：使用K-means将所有向量聚类

向量空间划分：
┌─────────────────────────────────┐
│                                 │
│  🔴簇1: [doc1, doc2, doc5]     │
│                                 │
│      🔵簇2: [doc3, doc7, doc9]  │
│                                 │
│  🟢簇3: [doc4, doc6, doc8]     │
│                                 │
└─────────────────────────────────┘

假设聚类为1024个簇
```

**查询过程：**

```
查询向量: [0.1, 0.2, ...]

步骤1：找到查询向量最近的nprobe=10个簇
    → 假设找到：簇1, 簇5, 簇12, ..., 簇998

步骤2：只在这10个簇中搜索
    → 原本需要搜索：1,000,000个文档
    → 现在只需要：1,000,000 / 1024 × 10 ≈ 10,000个文档
    → 速度提升：100倍！

步骤3：返回Top-K结果

优势：速度快
劣势：可能漏掉边界向量（召回率95-99%）
```

#### 方案C：HNSW（分层图索引）
**适用：> 1M条数据**

**构建过程：**

```
构建多层图结构（类似"六度分离"）：

第3层（最顶层）：稀疏连接
    节点A ─────── 节点B
           远距离跳跃
           
第2层：中等连接
    节点C ── 节点D ── 节点E
         中距离搜索
         
第1层：密集连接
    节点F ─ 节点G ─ 节点H ─ 节点I
         精确搜索
         
第0层（底层）：所有向量
    [所有1,000,000个向量的完整图]
```

**查询过程：**

```
查询向量: [0.1, 0.2, ...]

步骤1：从顶层（第3层）开始
    → 快速跳转到大致区域
    → 找到最近的节点B

步骤2：下降到第2层
    → 在节点B周围搜索
    → 找到更精确的节点D

步骤3：下降到第1层
    → 继续精细化
    → 找到节点G

步骤4：在底层（第0层）
    → 在节点G的邻居中搜索
    → 返回Top-K结果

优势：极快（QPS可达10,000+）
劣势：构建慢、占内存多
```

## 实际使用

### 代码示例

```python
from pymilvus import Collection

# ========== 步骤1：创建索引（离线，一次性）==========

# 稀疏向量索引（倒排索引）
sparse_index = {
    "index_type": "SPARSE_INVERTED_INDEX",
    "metric_type": "IP"  # 内积
}
collection.create_index("sparse_vector", sparse_index)

# 密集向量索引（自动选择）
dense_index = {
    "index_type": "AUTOINDEX",
    "metric_type": "IP"  # 内积
}
collection.create_index("dense_vector", dense_index)

# ========== 步骤2：加载到内存（必须！）==========
collection.load()

# ========== 步骤3：搜索（在线，实时）==========
search_params = {
    "metric_type": "IP",  # 必须与索引的metric_type一致
    "params": {}          # AUTOINDEX不需要额外参数
}

results = collection.search(
    data=[query_vector],
    anns_field="dense_vector",
    param=search_params,
    limit=10
)
```

### 度量类型选择

```python
# IP（Inner Product）- 内积
# 适合：归一化后的向量（如BGE、Sentence-BERT）
# 公式：similarity = Σ(a[i] × b[i])
# 范围：[-∞, +∞]，越大越相似
metric = "IP"

# COSINE - 余弦相似度
# 适合：未归一化的向量
# 公式：similarity = (A·B) / (||A|| × ||B||)
# 范围：[-1, 1]，1表示相同方向
metric = "COSINE"

# L2 - 欧氏距离
# 适合：地理坐标、物理空间
# 公式：distance = √(Σ(a[i] - b[i])²)
# 范围：[0, +∞]，越小越相似
metric = "L2"
```

## 常见问题

### Q1: 为什么需要两种索引？

```
稀疏向量（250,000维，<1%非零）和密集向量（768维，100%非零）
的数据特性完全不同，需要不同的索引策略：

稀疏向量 → 倒排索引（只索引非零维度）
密集向量 → 图/聚类索引（需要空间划分）
```

### Q2: 创建索引后必须load()吗？

```
是的！

create_index() → 创建索引结构（存储在磁盘）
load()         → 加载到内存（才能搜索）

没有load()就搜索会报错！
```

### Q3: AUTOINDEX会自动选择什么？

```
数据量 < 8,192条      → FLAT（精确）
数据量 8K - 1M条      → IVF_FLAT（快速）
数据量 > 1M条         → HNSW（极快）
```

### Q4: IP和COSINE有什么区别？

```
如果向量已归一化（||v|| = 1）：
IP = COSINE（结果完全相同）

BGE等模型输出已归一化，用IP更快（省去归一化计算）
```
