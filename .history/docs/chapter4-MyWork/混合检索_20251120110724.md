# 混合检索

混合检索（Hybird Search）结合稀疏向量和密集向量检索，旨在同时利用稀疏向量的关键词精准匹配和密集向量的语义匹配能力，提高检索效果。

## 稀疏向量 vs 密集向量

### 稀疏向量（Sparse Vector）

**定义**：基于词频统计的高维向量表示，其中绝大多数元素为零值。

**核心特征**：

- **维度**：通常为词汇表大小（10^4 ~ 10^6维）
- **非零率**：< 1%（大部分维度为0）
- **计算方法**：TF-IDF(Term 
Frequency-Inverse Document Frequency) 、BM25(Best Matching 25)等统计方法
- **表示方式**：词袋模型（Bag of Words），每个维度对应词汇表中的一个词
- **检索原理**：基于精确词匹配和词频权重

**优势**：可解释性强、关键词匹配精准、无需训练  
**局限**：无语义理解能力，同义词无法匹配

---

### 密集向量（Dense Vector）

**定义**：通过深度学习模型编码的低维连续向量表示，每个维度都包含有意义的数值。

**核心特征**：

- **维度**：通常为固定低维（384 ~ 1536维）
- **非零率**：≈ 100%（所有维度均为非零实数）
- **计算方法**：预训练语言模型（BERT、BGE、Sentence Transformers等）
- **表示方式**：语义空间中的点，相似语义在向量空间中距离接近
- **检索原理**：基于向量相似度（余弦相似度、欧式距离等）

**优势**：语义理解能力强、可捕捉同义词和语义相关性  
**局限**：可解释性差、计算和存储成本较高

## BM25：最佳匹配25算法详解

BM25（Best Matching 25）是一种概率检索模型，由Robertson和Walker在1994年提出，是TF-IDF的改进版本。它通过引入**词频饱和**和**文档长度归一化**机制，解决了TF-IDF的主要缺陷，成为现代搜索引擎（如Elasticsearch）的默认排序算法。

### 1. BM25 核心公式

$$ Score(Q, D) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{avgdl})} $$

**公式组成部分**：
- **$Q$**：查询（Query），包含 $n$ 个查询词
- **$D$**：待评分的文档（Document）
- **$q_i$**：查询中的第 $i$ 个词
- **$f(q_i, D)$**：查询词 $q_i$ 在文档 $D$ 中的词频（Term Frequency）
- **$|D|$**：文档 $D$ 的长度（词数）
- **$avgdl$**：文档集合中所有文档的平均长度

### 2. IDF 计算（逆文档频率）

$$ IDF(q_i) = \ln\left(\frac{N - n(q_i) + 0.5}{n(q_i) + 0.5} + 1\right) $$

其中：
- **$N$**：文档集合的总文档数
- **$n(q_i)$**：包含查询词 $q_i$ 的文档数
- **加0.5**：平滑因子，避免除零和负值

**IDF特性**：
- 常见词（如"的"、"是"）：$n(q_i)$ 接近 $N$，IDF ≈ 0
- 罕见词（如专业术语）：$n(q_i)$ 很小，IDF 很大
- 作用：降低常见词权重，提升罕见词权重

### 3. 核心参数详解

#### 参数 $k_1$：词频饱和参数（默认值：1.2 ~ 2.0）

控制词频对得分的影响程度，解决"词频线性增长"问题。

**作用机制**：
- **$k_1$ 较小（如0.5）**：词频饱和快，词出现3次和10次差异不大
- **$k_1$ 较大（如3.0）**：词频饱和慢，词频增长对得分影响更大
- **典型值 $k_1=1.2$**：平衡效果，词频从1增到10时得分增长显著，但继续增长时边际收益递减

**示例对比**（假设 $k_1=1.2$）：
| 词频 | TF-IDF得分 | BM25得分 |
|------|-----------|---------|
| 1 | 1.0 | 1.0 |
| 5 | 5.0 | 2.83 |
| 10 | 10.0 | 3.92 |
| 50 | 50.0 | 7.45 |

可见BM25在高词频时增长趋于平缓（饱和效应）。

#### 参数 $b$：文档长度归一化参数（默认值：0.75）

控制文档长度对得分的影响程度，解决"长文档偏见"问题。

**作用机制**：
- **$b=0$**：完全不考虑文档长度，长短文档平等对待
- **$b=1$**：完全按文档长度归一化，长文档受到最大惩罚
- **$b=0.75$**（推荐）：适度考虑文档长度，平衡长短文档

**文档长度归一化项**：
$$ 1 - b + b \cdot \frac{|D|}{avgdl} $$

- 文档长度 $= avgdl$：归一化项 $= 1$（无影响）
- 文档长度 $> avgdl$：归一化项 $> 1$（降低得分）
- 文档长度 $< avgdl$：归一化项 $< 1$（提升得分）

### 4. BM25 vs TF-IDF：核心改进

| 特性 | TF-IDF | BM25 |
|------|--------|------|
| **词频处理** | 线性增长，无上限 | 非线性饱和，有上限 |
| **文档长度** | 简单归一化或忽略 | 精细的长度惩罚机制 |
| **参数调优** | 无参数 | $k_1$、$b$ 可调节 |
| **理论基础** | 启发式统计 | 概率检索模型 |
| **检索效果** | 基础 | 更优（工业标准） |

**BM25的两大创新**：
1. **词频饱和**：防止"词汇堆砌"攻击，一个词出现100次不会比10次重要10倍
2. **文档长度归一化**：长文档虽然包含更多词，但不应因此获得不公平优势

### 5. 实际计算示例

假设有3个文档和1个查询：

**文档集合**：
- 文档1（20词）："机器学习 是 人工智能 的 分支 …"（"机器学习"出现2次）
- 文档2（50词）："深度学习 神经网络 …"（"机器学习"出现1次）
- 文档3（10词）："机器学习 很 重要"（"机器学习"出现1次）

**查询**："机器学习"

**参数设置**：$k_1=1.2$，$b=0.75$，$N=3$，$avgdl=(20+50+10)/3≈26.7$

#### 步骤1：计算IDF

包含"机器学习"的文档数 $n=3$：

$$ IDF = \ln\left(\frac{3-3+0.5}{3+0.5}+1\right) = \ln\left(\frac{0.5}{3.5}+1\right) \approx 0.13 $$

#### 步骤2：计算各文档得分

**文档1**（$|D|=20$，$f=2$）：

$$ Score_1 = 0.13 \times \frac{2 \times 2.2}{2 + 1.2 \times (1-0.75+0.75 \times \frac{20}{26.7})} \approx 0.13 \times 2.06 = 0.268 $$

**文档3**（$|D|=10$，$f=1$）：

$$ Score_3 = 0.13 \times \frac{1 \times 2.2}{1 + 1.2 \times (1-0.75+0.75 \times \frac{10}{26.7})} \approx 0.13 \times 1.85 = 0.241 $$

**排序结果**：文档1 > 文档3，因为文档1虽然较长但词频更高。

### 6. BM25 在代码中的应用

```python
from rank_bm25 import BM25Okapi
import jieba

# 文档集合（已分词）
documents = [
    "机器 学习 是 人工智能 的 重要 分支".split(),
    "深度 学习 是 机器 学习 的 子集".split(),
    "自然 语言 处理 应用 机器 学习".split()
]

# 初始化BM25模型
bm25 = BM25Okapi(documents)

# 查询（已分词）
query = "机器 学习 应用".split()

# 计算得分
scores = bm25.get_scores(query)
print(f"文档得分: {scores}")

# 获取Top-K文档
top_docs = bm25.get_top_n(query, documents, n=2)
print(f"Top-2文档: {top_docs}")
```

### 7. BM25 的优势与局限

#### 优势

- **非线性词频**：解决词汇堆砌问题，更符合人类阅读习惯
- **长度归一化**：公平对待不同长度的文档
- **参数可调**：可根据具体场景优化 $k_1$ 和 $b$
- **工业验证**：被Elasticsearch、Lucene等广泛采用
- **计算高效**：无需训练，在线计算快速

#### 局限

- **仍是词法匹配**：无法理解"汽车"和"轿车"是同义词
- **依赖分词质量**：中文场景需要准确的分词
- **参数敏感**：不同领域最优参数可能不同
- **无语义理解**：无法处理改写、同义、多义等语义问题

### 8. BM25 参数调优建议

| 场景 | $k_1$ 建议 | $b$ 建议 | 说明 |
|------|-----------|---------|------|
| **短文本**（如标题） | 1.2 ~ 1.5 | 0.3 ~ 0.5 | 降低长度归一化 |
| **长文本**（如文章） | 1.5 ~ 2.0 | 0.75 ~ 0.9 | 增强长度惩罚 |
| **混合长度** | 1.2 | 0.75 | 默认平衡值 |
| **关键词密集** | 0.8 ~ 1.0 | 0.5 | 降低词频饱和 |

**调优方法**：
1. 准备测试查询集和相关性标注
2. 网格搜索 $k_1 \in [0.5, 3.0]$，$b \in [0, 1]$
3. 评估指标：NDCG、MRR、Precision@K
4. 选择性能最优的参数组合


## TF-IDF：词频与逆文档频率详解

TF-IDF（Term Frequency-Inverse Document Frequency）是信息检索和文本挖掘中常用的权重计算方法，用于评估一个词在文档中的重要程度。它由两个部分组成：**词频（TF）**和**逆文档频率（IDF）**。

### 1. 词频（Term Frequency, TF）

**词频**衡量一个词在**单个文档**中出现的频率。词频越高，说明该词在该文档中越重要。

#### 计算公式

常见的TF计算方法有：

**方法一：原始词频**
$$ TF(t, d) = \frac{词t在文档d中出现的次数}{文档d的总词数} $$

**方法二：对数归一化（常用）**
$$ TF(t, d) = \log(1 + f(t, d)) $$

其中 $f(t, d)$ 是词 $t$ 在文档 $d$ 中出现的次数。

#### 示例

假设有一个文档："我喜欢机器学习。机器学习很有趣。"

- 文档总词数：8
- "机器学习"出现次数：2
- 原始TF = 2/8 = 0.25
- 对数TF = log(1 + 2) ≈ 1.099

### 2. 逆文档频率（Inverse Document Frequency, IDF）

**逆文档频率**衡量一个词在**整个文档集合**中的稀有程度。如果一个词在很多文档中都出现（如"的"、"是"等停用词），它的IDF值就低；如果一个词只在少数文档中出现（如专业术语），它的IDF值就高。

#### 计算公式

$$ IDF(t, D) = \log\frac{文档集合D的总文档数}{包含词t的文档数 + 1} $$

通常加1是为了避免分母为0的情况（平滑处理）。

#### 示例

假设有一个包含1000个文档的集合：

- 词"的"出现在990个文档中：IDF = log(1000/991) ≈ 0.004（非常低）
- 词"机器学习"出现在10个文档中：IDF = log(1000/11) ≈ 1.96（较高）
- 词"量子计算"出现在2个文档中：IDF = log(1000/3) ≈ 2.52（很高）

### 3. TF-IDF 综合计算

TF-IDF值 = TF × IDF，它同时考虑了：
- **局部重要性**（TF）：词在当前文档中的频率
- **全局重要性**（IDF）：词在整个文档集合中的稀有程度

#### 完整公式

$$ TF\text{-}IDF(t, d, D) = TF(t, d) \times IDF(t, D) $$

#### 实际例子

假设文档集合包含3个文档：

- **文档1**："我喜欢机器学习"
- **文档2**："机器学习很有趣"
- **文档3**："我喜欢编程"

计算词"机器学习"在文档1中的TF-IDF：

1. **TF计算**：
   - 文档1总词数：4
   - "机器学习"出现次数：1
   - TF = 1/4 = 0.25

2. **IDF计算**：
   - 文档总数：3
   - 包含"机器学习"的文档数：2（文档1和文档2）
   - IDF = log(3/3) = log(1) = 0

3. **TF-IDF**：
   - TF-IDF = 0.25 × 0 = 0

> **注意**：如果词在所有文档中都出现，IDF为0，TF-IDF也为0。这说明该词没有区分度。

再计算词"编程"在文档3中的TF-IDF：

1. **TF**：1/4 = 0.25
2. **IDF**：log(3/1) ≈ 1.099（"编程"只在文档3中出现）
3. **TF-IDF**：0.25 × 1.099 ≈ 0.275

### 4. TF-IDF 在代码中的应用

在混合检索代码中，TF-IDF通过 `sklearn.feature_extraction.text.TfidfVectorizer` 实现：

```python
from sklearn.feature_extraction.text import TfidfVectorizer

# 初始化TF-IDF向量化器
tfidf_vectorizer = TfidfVectorizer(
    max_features=10000,  # 限制词汇表大小
    stop_words='english',  # 移除停用词
    ngram_range=(1, 2)    # 使用1-gram和2-gram
)

# 拟合模型（学习词汇表和IDF值）
tfidf_vectorizer.fit(documents)

# 将文档转换为稀疏向量
sparse_vectors = tfidf_vectorizer.transform(documents)
```

#### 工作流程

1. **拟合阶段**（`fit`）：
   - 构建词汇表（所有唯一的词）
   - 计算每个词的IDF值
   - 存储词汇表到ID的映射

2. **转换阶段**（`transform`）：
   - 对每个文档计算每个词的TF值
   - 将TF与IDF相乘得到TF-IDF值
   - 生成稀疏向量（只存储非零值）

#### 稀疏向量表示

假设词汇表大小为10000，"机器学习"在词汇表中的索引是88，其TF-IDF值为0.275，那么稀疏向量可以表示为：

```python
# 字典格式
{88: 0.275}

# 或坐标列表格式（维度，索引列表，值列表）
(10000, [88], [0.275])
```

### 5. TF-IDF 的优势与局限

#### 优势

- **简单有效**：无需训练，计算快速
- **可解释性强**：每个维度对应一个具体的词
- **关键词匹配精准**：对专业术语和特定名词效果好
- **自动降权**：常见词（如停用词）自动获得低权重

#### 局限

- **无法理解语义**：不能识别"汽车"和"轿车"是同义词
- **维度极高**：词汇表可能达到数万甚至数十万维
- **稀疏性**：绝大多数维度为零，存储和计算需要特殊优化
- **依赖词频**：对于短文本或新词效果有限

### 6. TF-IDF vs BM25

虽然TF-IDF是经典方法，但在实际检索中，**BM25**（Best Matching 25）通常表现更好：

| 特性 | TF-IDF | BM25 |
|------|--------|------|
| 词频处理 | 线性增长 | 有上限（饱和） |
| 文档长度归一化 | 简单 | 更精细 |
| 参数调优 | 无 | 有k1、b等参数 |
| 检索效果 | 基础 | 更优 |

BM25在TF-IDF基础上引入了词频饱和和文档长度归一化，使得检索结果更加合理。

---

> **总结**：TF-IDF通过词频和逆文档频率的组合，能够有效识别文档中的关键词。在混合检索中，TF-IDF生成的稀疏向量与深度学习模型生成的密集向量互补，共同提升检索效果。
