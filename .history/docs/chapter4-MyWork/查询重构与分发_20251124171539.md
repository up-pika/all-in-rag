# 查询重构与分发

检索之前对用户查询进行预处理，包括查询重构和查询分发。查询重构旨在将用户查询转化为搜索引擎能够理解的形式，查询分发旨在将用户查询分发到多个索引中，从而提高查询的召回率。

此阶段包含两个关键技术：

1. 查询翻译：将用户的原始问题转换为一个或多个更适合检索的查询形式。
2. 查询路由：根据问题的性质，将其智能地分发大最合适的数据源或检索器。

## 查询翻译

查询翻译旨在弥合用户自然语言提问与文档库存储信息之间的语义鸿沟。可通过重写、分解或扩展查询显著提升检索的准确率

### 1. 提示工程

提示工程（Prompt Engineering）是一种将用户查询转化为搜索引擎能够理解的形式的方法。它通过设计一系列的提示词，引导用户输入更加精确的查询，从而提高检索的准确率。

例如，对于用户查询“苹果手机”，可以通过设计一系列的提示词，如“苹果手机价格”、“苹果手机最新款”、“苹果手机评价”等，引导用户输入更加精确的查询，从而提高检索的准确率。

例如，采用更高级的提示工程技巧：让LLM直接构建出查询指令。采用这个方法可以解决“时间最短的视频”这类需要排序或比较的查询。

### 2. 多查询分解

多查询分解（Multi-query Decomposition）是一种将用户查询分解为多个子查询的方法。通过将用户查询分解为多个子查询，可以更好地理解用户的意图，从而提高检索的准确率。

例如，对于用户查询“苹果手机价格”，可以将其分解为两个子查询：“苹果手机”和“价格”，从而更好地理解用户的意图。

### 3. 退步提示

退步提示是由 Google DeepMind 团队提出的一种旨在提升大语言模型推理能力的提示工程技巧2。当面对一个细节繁多或过于具体的问题时，模型直接作答（即便是使用思维链）也容易出错。退步提示通过引导模型“退后一步”来解决这个问题。

其核心流程分为两步：

1. 抽象化：引导 LLM 从用户的原始具体问题中，生成一个更高层次、更概括的“退步问题”（Step-back Question）。这个退步问题旨在探寻原始问题背后的通用原理或核心概念。
2. 推理：系统会先获取“退步问题”的答案（例如，一个物理定律、一段历史背景等），然后将这个通用原理作为上下文，再结合原始的具体问题，进行推理并生成最终答案。

### 4. 假设性文档侵入

假设性文档嵌入（Hypothetical Document Embeddings, HyDE）是一种无需微调即可显著提升向量检索质量的查询改写技术。核心是解决一个普遍存在于检索任务中的难题：用户的查询（Query）通常简短、关键词有限，而数据库中存储的文档则内容详实、上下文丰富，两者在语义向量空间中可能存在“鸿沟”，导致直接用查询向量进行搜索效果不佳。

HyDE的巧妙之处：不直接使用用户的原始查询，而是先利用LLM生成一个假设性的，能够完美回答该查询的文档。然后，HyDE将这个假设性文档的向量表示作为查询向量，进行检索。

通过此法，将困难的“查询-文档”匹配问题转化为相对容易的“文档-文档”匹配问题。

## 查询路由

**查询路由（Query Routing）** 是用于优化复杂 RAG 系统的一项关键技术。当系统接入了多个不同的数据源或具备多种处理能力时，就需要一个“智能调度中心”来分析用户的查询，并动态选择最合适的处理路径。其本质是替代硬编码规则，通过语义理解将查询分发至最匹配的数据源、处理组件或提示模板，从而提升系统的效率与答案的准确性。

### 1 应用场景

查询路由的应用场景十分广泛。

1.  **数据源路由**：这是最常见的场景。根据查询意图，将其路由到不同的知识库。例如：
    *   查询“最新的 iPhone 有什么功能？” -> 路由到**产品文档向量数据库**。
    *   查询“我上次订购了什么？” -> 路由到**用户历史SQL数据库**（执行Text-to-SQL）。
    *   查询“A公司和B公司的投资关系是怎样的？” -> 路由到**企业知识图谱数据库**。

2.  **组件路由**：根据问题的复杂性，将其分配给不同的处理组件，以平衡成本和效果。
    *   简单FAQ → 直接进行向量检索，速度快、成本低。
    *   复杂操作或需要与外部API交互 → 调用 Agent 来执行任务。

3.  **提示模板路由**：为不同类型的任务动态选择最优的提示词模板，以优化生成效果。
    *   数学问题 → 选用包含分步思考（Step-by-Step）逻辑的提示模板。
    *   代码生成 → 选用专门为代码优化过的提示模板。

### 2.实现方法

#### 2.1 基于LLM的意图识别

通过设计一套清晰的路由选项的提示词，让LLM直接对用户查询进行分类，并输出一个代表路由选择的标签。核心在于构建“分类-分发”流水线。

实现流程：

1. 定义清晰的路由选项（例如，数据源名称、功能分类）。
2. LLM 分析查询并输出决策标签。
3. 代码根据标签调用相应的检索器或工具。

#### 2.2 嵌入相似性路由

通过计算用户查询与预设的“路由示例语句”之间的向量嵌入相似度来做出决策。不依赖LLM进行分类，延迟较低。

实现流程：

1. 定义路由描述并向量化。为每个路由创建一个详细的文本描述，并使用嵌入模型将其转换为向量，供后续相似度计算使用。
2. 定义目标链。创建路由最终要分发到的目标处理链，并用一个字典 route_map 将路由名称和链对应起来。
3. 定义路由函数。根据查询的向量嵌入，计算其与每个路由描述的相似度，并选择相似度最高的路由，调用相应的处理链。
4. 组合并调用。将路由函数与检索器结合，形成完整的查询处理流程。

3.  捞出后，**浸入备好的肉汤或温水中**，防止粘连和变干。

**第三步：熬制味汤（成其魂）**

1.  用锅里煸炒肉臊的底油，如果不够可以再加一些。**油温五成热**时，下入剁细的**郫县豆瓣酱**。
2.  用中小火耐心煸炒，直到炒出**红油和酱香味**，这是菜色红亮的关键。
3.  紧接着下入**豆豉末、姜末、蒜末**，继续翻炒出复合香味。

1.  将沥干水分的豆腐块轻轻滑入锅中，用勺子背轻轻推匀（切忌用锅铲翻炒，豆腐会碎）。
2.  用中火烧制，让豆腐慢慢吸收汤汁的味道，约3-5分钟。

    *   **第二次勾芡**：汤汁再次沸腾后，淋入水淀粉，汤汁更为浓稠。
    *   **第三次勾芡**：在起锅前，淋入剩余水淀粉，汤汁完全包裹在豆腐上，达到“亮汁亮油”的效果。
4.  在第二次勾芡后，撒入大部分的“马耳朵”蒜苗白。

1.  将烧好的豆腐盛入预热过的碗中（保持“烫”的口感）。
2.  在表面均匀撒上之前炒好的**牛肉酥臊**。
3.  **最关键的一步**：在肉臊之上，厚厚地撒上一层**现舂的汉源花椒面**。滚烫的豆腐会瞬间激发出花椒的霸道的麻香。
4.  最后，用剩余的蒜苗叶尖稍作点缀。

路由决策: 粤菜
回答: 好的，师傅！坐低饮啖茶，听我慢慢同你讲解。白切鸡，係我哋粤菜嘅头牌，看似简单，实则係功夫菜。精髓就在于“浸”同“过冷河”，追求鸡皮爽脆、鸡肉鲜嫩、骨髓带血丝嘅至高境界。

### **第一：选鸡係根基**

*   **品种**：首选**清远麻鸡**或者**三黄鸡**，大约2斤半到3斤左右。呢种鸡皮薄肉嫩，脂肪均匀，做白切鸡最靓。
*   **状态**：一定要用**新鲜光鸡**，冰鲜鸡风味差好远。最好係当日宰杀嘅。

### **第二：备料要纯粹**

*   **主料**：靓鸡一只（约1500克）
*   **汤底料**：生姜几大块（拍扁）、葱一把（打成结）、黄酒或广东米酒少许。
*   **蘸料灵魂**：
    *   **姜葱蓉**：生姜磨成极细嘅蓉，干葱头或红葱头切碎，撒少少盐，淋上滚烫嘅花生油，激发出香味。
    *   **豉油皇**：上好嘅头抽（生抽），可以加入少少糖、鸡汤、姜葱油调匀，味道更有层次。

### **第三：浸鸡乃核心功夫（关键步骤）**

呢个步骤，差一分火候都唔得。

1.  **“虾眼水”准备**：用一个大汤锅，装入足够淹没全鸡嘅清水。放入姜块、葱结，烧滚后，淋入少少米酒。然后将火调至**微沸状 态**，即係水面只冒起好似虾眼咁细密嘅气泡，而唔係大滚大沸。大滚会令鸡皮爆裂，肉质变柴。

2.  **“三提三浸”**：拎住鸡颈，将鸡身放入“虾眼水”中，浸没全身，**默数10秒**，然后提起，让鸡腹腔内嘅水流出。重复呢个动作 三次。呢一步叫“吊水”，目的係令鸡皮内外温度一致，鸡皮迅速收缩，变得爽脆，同时锁住肉汁。

3.  **文火浸熟**：第三次浸完后，将成只鸡完全浸入水中。如果鸡会浮起，可以用个碟子轻轻压住。**立即熄火**！

4.  **计时浸焗**：
    *   根据鸡嘅大小同室温，靠水嘅余温将鸡浸熟。以3斤鸡为例，**浸焗约25-30分钟**。期间切记唔好开盖，让热量均匀渗透。   
    *   点判断熟唔熟？用一只竹签或者筷子，喺鸡髀最厚嘅位置插入，如果可以轻易插入，而且拔出嘅筷子孔流出嘅汁水係清澈透明 嘅（唔带血水），就代表熟咗。如果汁水带红，就要再浸多几分钟。

### **第四：过冷河定乾坤**

呢一步係鸡皮爽脆嘅终极秘诀！

1.  准备一大盘**冰水**，最好係冰粒加冻开水，越冻越好。
2.  鸡浸够时间后，立刻捞起，**马上放入冰水**中，完全浸没，直至鸡身完全冷却。呢个冷热交替嘅过程，叫做“过冷河”，能让鸡皮 同肉质瞬间收缩，形成爽脆弹牙嘅口感，同时阻止余温将鸡肉继续加热变老。
3.  冷却后（约15-20分钟），捞起，沥干水份。

### **第五：斩件摆盘见功力**

1.  鸡身涂上一层薄薄嘅熟油或者麻油，可以让鸡皮更加光泽亮丽。
2.  **斩鸡**：用重身嘅砧板同锋利嘅刀。先卸下鸡翅、鸡腿，再将鸡身剖开。落刀要快、准、狠，尽量一刀过，避免来回锯，咁先可 以保持鸡件切口整齐，唔会骨肉碎烂。
3.  按传统摆盘：将鸡头、鸡颈放于碟底，再将斩好嘅鸡件（骨肉均匀）铺面，砌返成一只完整嘅鸡形。

回答: 您好！关于「番茄炒蛋是否需要放糖」这个问题，其实并没有绝对的标准答案，主要取决于个人口味和饮食习惯。我们可以从几 个角度来分析，帮助您做出最适合自己的选择：

### 1. **支持放糖的理由**
   - **平衡酸味**：番茄（尤其是未完全成熟或反季番茄）带有较明显的酸味，加入少量糖可以中和酸度，使口感更柔和。

   - **地方习惯**：中国部分地区（如上海、江苏等）的烹饪习惯中，番茄炒蛋常会加少许糖，形成“酸甜咸鲜”的复合口味。        

### 2. **不建议放糖的理由**
   - **保留自然风味**：成熟度高的优质番茄自带清甜，不加糖更能突出食材本味。

   - **咸鲜派偏好**：北方部分地区或传统做法中，番茄炒蛋更强调咸鲜口味，仅用盐调味。

### 3. **折中方案与技巧**
   - **少量尝试**：如果不确定，可以先加半茶匙糖（约2-3克），翻炒后尝味再调整。
