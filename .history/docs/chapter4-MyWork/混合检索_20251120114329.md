# 混合检索

混合检索（Hybird Search）结合稀疏向量和密集向量检索，旨在同时利用稀疏向量的关键词精准匹配（精确性）和密集向量的语义匹配能力（泛化性），提高检索效果。

## 稀疏向量 vs 密集向量

### 稀疏向量（Sparse Vector）

**定义**：基于词频统计的高维向量表示，其中绝大多数元素为零值。

**核心特征**：

- **维度**：通常为词汇表大小（10^4 ~ 10^6维）
- **非零率**：< 1%（大部分维度为0）
- **计算方法**：TF-IDF(Term 
Frequency-Inverse Document Frequency) 、BM25(Best Matching 25)等统计方法
- **表示方式**：词袋模型（Bag of Words），每个维度对应词汇表中的一个词
- **检索原理**：基于精确词匹配和词频权重

**优势**：可解释性强、关键词匹配精准、无需训练  
**局限**：无语义理解能力，同义词无法匹配

---

### 密集向量（Dense Vector）

**定义**：通过深度学习模型编码的低维连续向量表示，每个维度都包含有意义的数值。

**核心特征**：

- **维度**：通常为固定低维（384 ~ 1536维）
- **非零率**：≈ 100%（所有维度均为非零实数）
- **计算方法**：预训练语言模型（BERT、BGE、Sentence Transformers等）
- **表示方式**：语义空间中的点，相似语义在向量空间中距离接近
- **检索原理**：基于向量相似度（余弦相似度、欧式距离等）

**优势**：语义理解能力强、可捕捉同义词和语义相关性  
**局限**：可解释性差、计算和存储成本较高

## 稀疏向量与密集向量的表示

### 稀疏向量表示

1. 字典/键值对：将非零元素的索引作为键，对应的词频或权重作为值。
2. 坐标列表（coordinate list-COO）:元组形式（维度，[索引列表],[值列表]）。这种格式常见于 SciPy 等科学计算库中。

### 密集向量表示

1. 向量：将每个文档的密集向量表示为一个低维向量，通常表示为一维浮点数数组。
2. 矩阵：将所有文档的密集向量表示为一个矩阵，每行对应一个文档的向量。

## 混合检索：技术原理与融合方法

混合检索（Hybrid Search）通过**并行执行**稀疏向量检索和密集向量检索，然后将两组结果**融合**成统一的排序列表，实现优势互补。

### 1. 核心工作流程

```
用户查询："机器学习在医疗中的应用"
    │
    ├─────────────────────┬─────────────────────┐
    ▼                     ▼                     ▼
稀疏向量生成          密集向量生成          元数据过滤
(BM25/TF-IDF)        (BGE/BERT)           (可选)
    │                     │                     │
["机器":0.5,          [0.23, -0.45,         category="medical"
 "学习":0.8,           0.67, ..., -0.12]
 "医疗":1.2,           (768维语义向量)
 "应用":0.6]
(稀疏权重)
    │                     │
    ▼                     ▼
稀疏索引检索          密集索引检索
(倒排索引)            (向量索引: HNSW/IVF)
    │                     │
    ▼                     ▼
结果集A               结果集B
Rank  Doc  Score      Rank  Doc  Score
1     D1   2.5        1     D3   0.92
2     D3   2.1        2     D1   0.88

    │                     │
    └─────────┬───────────┘
              ▼

        1. D1 (综合得分最高)
        2. D3
        3. D2
        4. D5
```

### 2. 融合方法详解

#### 方法一：倒数排序融合（RRF - Reciprocal Rank Fusion）

**核心思想**：不关心原始得分，只关心**排名**。一个文档在多个检索系统中排名越靠前，融合得分越高。

**公式**：

$$ RRF_{score}(d) = \sum_{i=1}^{k} \frac{1}{rank_i(d) + c} $$

**参数说明**：
- $d$：待评分的文档
- $k$：检索系统数量（通常为2：稀疏+密集）
- $rank_i(d)$：文档 $d$ 在第 $i$ 个检索系统中的排名（从1开始）
- $c$：常数（通常为60），用于**平滑排名**，降低排名靠后文档的影响

**计算示例**：

假设文档D1在两个检索系统中的排名：
- 稀疏检索排名：第1名
- 密集检索排名：第2名

```python
# c = 60
RRF_score(D1) = 1/(1+60) + 1/(2+60)
              = 1/61 + 1/62
              = 0.01639 + 0.01613
              = 0.03252
```

**完整示例对比**：

| 文档 | 稀疏排名 | 密集排名 | RRF得分计算 | 最终RRF得分 | 最终排名 |
|------|---------|---------|------------|-----------|---------|
| D1 | 1 | 2 | 1/61 + 1/62 | 0.03252 | **1** |
| D3 | 2 | 1 | 1/62 + 1/61 | 0.03252 | **1** |
| D2 | 4 | 3 | 1/64 + 1/63 | 0.03150 | **3** |
| D5 | 3 | 4 | 1/63 + 1/64 | 0.03150 | **3** |
| D6 | 5 | - | 1/65 + 0 | 0.01538 | 5 |
| D7 | - | 5 | 0 + 1/65 | 0.01538 | 5 |

**RRF优势**：
- ✅ **简单鲁棒**：不需要归一化不同量纲的得分
- ✅ **无需调参**：$c=60$ 是经验最优值，通用性强
- ✅ **公平性好**：避免某个检索系统得分过高而主导结果
- ✅ **处理缺失**：某文档只在一个系统中出现，不影响计算

**RRF局限**：
- ❌ 无法调整不同检索系统的**权重比例**
- ❌ 丢失了原始得分的**绝对信息**

**代码实现**：

```python
from pymilvus import RRFRanker, AnnSearchRequest

# 1. 生成查询向量
query_embeddings = ef([search_query])
dense_vec = query_embeddings["dense"][0]
sparse_vec = query_embeddings["sparse"]

# 2. 创建RRF融合器
rerank = RRFRanker(k=60)  # k为平滑参数

# 3. 创建两个独立的搜索请求
dense_req = AnnSearchRequest([dense_vec], "dense_vector", 
                             {"metric_type": "IP"}, limit=10)
sparse_req = AnnSearchRequest([sparse_vec], "sparse_vector", 
                              {"metric_type": "IP"}, limit=10)

# 4. 执行混合搜索
results = collection.hybrid_search(
    [sparse_req, dense_req],  # 多个搜索请求
    rerank=rerank,            # RRF融合
    limit=5                   # 最终返回Top-5
)
```

---

#### 方法二：加权线性组合（Weighted Score Fusion）

**核心思想**：将稀疏和密集检索的原始得分通过**权重参数α**进行线性组合。

**公式**：

$$ Hybrid_{score}(d) = \alpha \cdot Dense_{score}(d) + (1-\alpha) \cdot Sparse_{score}(d) $$

**参数说明**：
- $\alpha \in [0, 1]$：密集向量的权重
- $1-\alpha$：稀疏向量的权重
- 需要先对得分进行**归一化**（如Min-Max或Z-score）

**权重选择策略**：

| 场景 | α值 | 说明 |
|------|-----|------|
| **关键词搜索** | 0.2-0.4 | 电商搜索、型号查询、专有名词检索 |
| **平衡搜索** | 0.5 | 通用场景，语义与关键词并重 |
| **语义搜索** | 0.6-0.8 | 问答系统、推荐系统、相似文档 |
| **纯语义** | 1.0 | 完全依赖语义，如多语言跨模态 |
| **纯关键词** | 0.0 | 完全依赖词法，如精确匹配 |

**计算示例**：

假设对文档D1的两种得分（已归一化到0-1）：
- 密集得分：0.85
- 稀疏得分：0.60
- α = 0.6（语义优先场景）

```python
Hybrid_score = 0.6 × 0.85 + 0.4 × 0.60
             = 0.51 + 0.24
             = 0.75
```

**完整示例**：

| 文档 | 密集得分 | 稀疏得分 | α=0.3 | α=0.5 | α=0.7 | 最优场景 |
|------|---------|---------|-------|-------|-------|---------|
| D1 | 0.92 | 0.45 | **0.59** | 0.69 | 0.78 | 语义相关但缺关键词 |
| D2 | 0.50 | 0.95 | **0.82** | 0.73 | 0.64 | 关键词完全匹配 |
| D3 | 0.85 | 0.80 | **0.82** | 0.83 | 0.84 | 语义和关键词都强 |

**得分归一化方法**：

```python
from sklearn.preprocessing import MinMaxScaler
import numpy as np

# 方法1：Min-Max归一化（推荐）
def normalize_scores(scores):
    """将得分归一化到[0, 1]"""
    scores = np.array(scores).reshape(-1, 1)
    scaler = MinMaxScaler()
    return scaler.fit_transform(scores).flatten()

# 方法2：Softmax归一化
def softmax_normalize(scores):
    """将得分转换为概率分布"""
    exp_scores = np.exp(scores - np.max(scores))
    return exp_scores / exp_scores.sum()

# 使用示例
dense_scores = [0.92, 0.75, 0.88, 0.65]
sparse_scores = [2.5, 1.8, 2.1, 1.2]

# 归一化
dense_norm = normalize_scores(dense_scores)
sparse_norm = normalize_scores(sparse_scores)

# 加权融合
alpha = 0.6
hybrid_scores = alpha * dense_norm + (1-alpha) * sparse_norm
```

**加权融合优势**：
- ✅ **灵活调节**：可根据业务需求调整权重
- ✅ **保留得分**：利用原始得分的绝对值信息
- ✅ **可解释性**：权重直观反映两种检索的重要性

**加权融合局限**：
- ❌ **需要归一化**：不同检索系统的得分量纲不同
- ❌ **参数调优**：α值需要大量实验确定最优值
- ❌ **得分依赖**：如果某个系统得分不准确，会影响融合效果

---

### 3. RRF vs 加权融合对比

| 维度 | RRF | 加权线性组合 |
|------|-----|------------|
| **输入** | 排名（Rank） | 原始得分（Score） |
| **归一化** | 不需要 | **必须归一化** |
| **参数** | 固定 $c=60$ | 需调优 $\alpha$ |
| **灵活性** | 低（无法调权重） | 高（可控制比例） |
| **鲁棒性** | 高（不受得分量纲影响） | 中（依赖得分质量） |
| **适用场景** | **通用场景**，快速部署 | **精细调优**，特定业务 |
| **工业应用** | Milvus默认方案 | Elasticsearch默认方案 |

**选择建议**：
- 🎯 **快速原型/通用场景**：优先选择RRF
- 🎯 **精细控制/特定业务**：使用加权线性组合
- 🎯 **不确定场景**：先用RRF验证效果，再考虑加权调优

### 4. 混合检索的优势与局限

#### 优势

| 优势 | 说明 | 实例 |
|------|------|------|
| **召回率提升** | 稀疏捕获关键词，密集捕获语义 | 查询"Python编程"，召回"Python开发"和"蟒蛇" |
| **鲁棒性增强** | 单一检索失效时，另一个补充 | 拼写错误时，密集向量仍可语义匹配 |
| **精准+泛化** | 关键词保证精准，语义提供泛化 | 电商：型号精确+相似商品推荐 |
| **跨语言能力** | 密集向量可跨语言，稀疏保留原语言 | 中文查询匹配英文文档（语义） |

#### 局限

| 局限 | 影响 | 解决方案 |
|------|------|---------|
| **计算成本高** | 需维护两套索引，查询时间翻倍 | 异步并行查询、索引优化 |
| **存储开销大** | 稀疏+密集向量都需存储 | 使用向量压缩（PQ、SQ） |
| **参数调优复杂** | α值、RRF的k值需实验确定 | A/B测试、自动调参 |
| **可解释性差** | 融合后很难解释为何排序 | 记录中间得分、可视化分析 |

# 补充知识

## BM25：最佳匹配25算法详解

BM25（Best Matching 25）是一种概率检索模型，由Robertson和Walker在1994年提出，是TF-IDF的改进版本。它通过引入**词频饱和**和**文档长度归一化**机制，解决了TF-IDF的主要缺陷，成为现代搜索引擎（如Elasticsearch）的默认排序算法。

### BM25 核心公式

  $$ Score(Q, D) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot (1 - b + b \cdot \frac{|D|}{avgdl})} $$

  其中：
  - $IDF(q_i)$: 查询词 $q_i$ 的逆文档频率，用于衡量一个词的普遍程度。越常见的词，IDF值越低。
  - $f(q_i, D)$: 查询词 $q_i$ 在文档 $D$ 中的词频。
  - $|D|$: 文档 $D$ 的长度。
  - $avgdl$: 集合中所有文档的平均长度。
  - $k_1, b$: 可调节的超参数。 $k_1$ 用于控制词频饱和度（一个词在文档中出现10次和100次，其重要性增长并非线性），  $b$ 用于控制文档长度归一化的程度。


## TF-IDF：词频与逆文档频率详解

TF-IDF（Term Frequency-Inverse Document Frequency）是信息检索和文本挖掘中常用的权重计算方法，用于评估一个词在文档中的重要程度。它由两个部分组成：**词频（TF）**和**逆文档频率（IDF）**。

### 1. 词频（Term Frequency, TF）

**词频**衡量一个词在**单个文档**中出现的频率。词频越高，说明该词在该文档中越重要。

#### 计算公式

常见的TF计算方法有：

**方法一：原始词频**
$$ TF(t, d) = \frac{词t在文档d中出现的次数}{文档d的总词数} $$

**方法二：对数归一化（常用）**
$$ TF(t, d) = \log(1 + f(t, d)) $$

其中 $f(t, d)$ 是词 $t$ 在文档 $d$ 中出现的次数。

#### 示例

假设有一个文档："我喜欢机器学习。机器学习很有趣。"

- 文档总词数：8
- "机器学习"出现次数：2
- 原始TF = 2/8 = 0.25
- 对数TF = log(1 + 2) ≈ 1.099

### 2. 逆文档频率（Inverse Document Frequency, IDF）

**逆文档频率**衡量一个词在**整个文档集合**中的稀有程度。如果一个词在很多文档中都出现（如"的"、"是"等停用词），它的IDF值就低；如果一个词只在少数文档中出现（如专业术语），它的IDF值就高。

#### 计算公式

$$ IDF(t, D) = \log\frac{文档集合D的总文档数}{包含词t的文档数 + 1} $$

通常加1是为了避免分母为0的情况（平滑处理）。

#### 示例

假设有一个包含1000个文档的集合：

- 词"的"出现在990个文档中：IDF = log(1000/991) ≈ 0.004（非常低）
- 词"机器学习"出现在10个文档中：IDF = log(1000/11) ≈ 1.96（较高）
- 词"量子计算"出现在2个文档中：IDF = log(1000/3) ≈ 2.52（很高）

### 3. TF-IDF 综合计算

TF-IDF值 = TF × IDF，它同时考虑了：
- **局部重要性**（TF）：词在当前文档中的频率
- **全局重要性**（IDF）：词在整个文档集合中的稀有程度

#### 完整公式

$$ TF\text{-}IDF(t, d, D) = TF(t, d) \times IDF(t, D) $$

#### 实际例子

假设文档集合包含3个文档：

- **文档1**："我喜欢机器学习"
- **文档2**："机器学习很有趣"
- **文档3**："我喜欢编程"

计算词"机器学习"在文档1中的TF-IDF：

1. **TF计算**：
   - 文档1总词数：4
   - "机器学习"出现次数：1
   - TF = 1/4 = 0.25

2. **IDF计算**：
   - 文档总数：3
   - 包含"机器学习"的文档数：2（文档1和文档2）
   - IDF = log(3/3) = log(1) = 0

3. **TF-IDF**：
   - TF-IDF = 0.25 × 0 = 0

> **注意**：如果词在所有文档中都出现，IDF为0，TF-IDF也为0。这说明该词没有区分度。

再计算词"编程"在文档3中的TF-IDF：

1. **TF**：1/4 = 0.25
2. **IDF**：log(3/1) ≈ 1.099（"编程"只在文档3中出现）
3. **TF-IDF**：0.25 × 1.099 ≈ 0.275

### 4. TF-IDF 在代码中的应用

在混合检索代码中，TF-IDF通过 `sklearn.feature_extraction.text.TfidfVectorizer` 实现：

```python
from sklearn.feature_extraction.text import TfidfVectorizer

# 初始化TF-IDF向量化器
tfidf_vectorizer = TfidfVectorizer(
    max_features=10000,  # 限制词汇表大小
    stop_words='english',  # 移除停用词
    ngram_range=(1, 2)    # 使用1-gram和2-gram
)

# 拟合模型（学习词汇表和IDF值）
tfidf_vectorizer.fit(documents)

# 将文档转换为稀疏向量
sparse_vectors = tfidf_vectorizer.transform(documents)
```

#### 工作流程

1. **拟合阶段**（`fit`）：
   - 构建词汇表（所有唯一的词）
   - 计算每个词的IDF值
   - 存储词汇表到ID的映射

2. **转换阶段**（`transform`）：
   - 对每个文档计算每个词的TF值
   - 将TF与IDF相乘得到TF-IDF值
   - 生成稀疏向量（只存储非零值）

#### 稀疏向量表示

假设词汇表大小为10000，"机器学习"在词汇表中的索引是88，其TF-IDF值为0.275，那么稀疏向量可以表示为：

```python
# 字典格式
{88: 0.275}

# 或坐标列表格式（维度，索引列表，值列表）
(10000, [88], [0.275])
```

### 5. TF-IDF 的优势与局限

#### 优势

- **简单有效**：无需训练，计算快速
- **可解释性强**：每个维度对应一个具体的词
- **关键词匹配精准**：对专业术语和特定名词效果好
- **自动降权**：常见词（如停用词）自动获得低权重

#### 局限

- **无法理解语义**：不能识别"汽车"和"轿车"是同义词
- **维度极高**：词汇表可能达到数万甚至数十万维
- **稀疏性**：绝大多数维度为零，存储和计算需要特殊优化
- **依赖词频**：对于短文本或新词效果有限

### 6. TF-IDF vs BM25

虽然TF-IDF是经典方法，但在实际检索中，**BM25**（Best Matching 25）通常表现更好：

| 特性 | TF-IDF | BM25 |
|------|--------|------|
| 词频处理 | 线性增长 | 有上限（饱和） |
| 文档长度归一化 | 简单 | 更精细 |
| 参数调优 | 无 | 有k1、b等参数 |
| 检索效果 | 基础 | 更优 |

BM25在TF-IDF基础上引入了词频饱和和文档长度归一化，使得检索结果更加合理。

---

> **总结**：TF-IDF通过词频和逆文档频率的组合，能够有效识别文档中的关键词。在混合检索中，TF-IDF生成的稀疏向量与深度学习模型生成的密集向量互补，共同提升检索效果。
